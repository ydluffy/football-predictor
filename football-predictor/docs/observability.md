# 可观测性与运行保障

FastAPI 服务通过统一中间件提供请求关联、结构化日志、进程内运行指标和分层健康检查，不需要额外运行监控组件。

## 请求追踪

每个 HTTP 响应都包含：

- `X-Request-ID`：沿用合法的客户端 ID，否则生成新的随机 ID；
- `X-Response-Time-Ms`：响应开始前的服务端处理耗时。

请求 ID 仅接受 1–128 位字母、数字、点、下划线、冒号和连字符，避免把任意请求头写入日志。聊天上游请求复用同一个 ID，因此可以从 API 访问日志关联到模型供应商调用及重试日志。

`artifacts/logs/app.log` 使用 JSON Lines 结构化格式，单条请求日志包含 `request_id`、HTTP 方法、路径、状态码和完整处理耗时。标准错误仍保留便于本地阅读的文本格式。

## 运行指标

`GET /metrics` 返回当前 Python 进程的轻量指标：

- 启动时间和运行时长；
- 请求、响应和正在处理的请求数；
- 4xx、5xx 数量，总错误率和服务端错误率；
- 平均与最大请求耗时。

这些计数在进程重启后归零，适合实例健康诊断。多实例长期趋势应由网关或监控平台定期采集，不能把该端点当作持久化指标库。

## 健康检查

| 端点 | 用途 |
| --- | --- |
| `GET /health/live` | 进程存活探针；只要事件循环可以响应就返回成功 |
| `GET /health/ready` | 流量就绪探针；模型未加载或数据质量报告明确失败时返回 HTTP 503 |
| `GET /health` | 完整诊断；兼容保留 `ok`、`model_loaded` 和 `model_path` 顶层字段 |

完整健康响应还包含服务版本、模型版本/类型/特征版本/制品摘要、数据快照版本、数据质量报告状态和请求指标。

模型版本默认取模型 manifest 的 SHA-256 前 12 位，数据快照版本默认取 `artifacts/eval/data_model_quality_gate.json` 的 `as_of_utc`。部署系统也可以显式设置 `MODEL_VERSION` 和 `DATA_SNAPSHOT_VERSION`，覆盖自动推断值。

当模型可用但没有数据质量报告时，`/health` 状态为 `degraded`，服务仍可接收流量；报告状态为 `fail` 或 `error` 时，就绪检查会阻断流量。
