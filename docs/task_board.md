# 多智能体任务看板

这份文件是给“你 + 多个智能体”协作用的轻量任务看板。它的作用是让任何一个智能体接手时，都能快速知道：

- 当前目标是什么
- 哪些任务在做
- 谁负责哪一块
- 下一步是什么
- 有哪些边界和禁止事项

你可以把它当成一个“项目唯一状态页”，并要求所有智能体在完成任务后更新这里。

## 当前协作规则摘要

1. 代码真源：GitHub
2. 业务数据真源：Supabase
3. 训练数据真源：外部存储（例如 Google Drive）
4. 生成产物：不入 Git，留在运行环境或外部存储
5. 正式自动化总控：当前只在本地环境运行

必读文档：

- `docs/collaboration_playbook.md`
- `docs/github_workflow.md`
- `docs/data_sync_and_sources.md`
- `docs/cloud_computer_setup.md`

## 角色分工

- 你：目标、优先级、合并决策、最终验收
- Trae Work：跨模块推进、规范与方案、前端与数据库建设、协作收口
- 本地 Codex：本地自动化总控、Python 侧实现、Git 提交与推送
- 云端电脑智能体：前端、文档、数据获取层对比迁移、实验任务

## 本周主目标

- 目标 A：把项目稳定搬到 GitHub 并形成稳定协作流
- 目标 B：确认 Supabase 数据库是否真实建好并可被 web 访问
- 目标 C：让云端电脑可以 clone 项目并参与前端/数据获取层协作
- 目标 D：为 Colab 训练准备好“可复制粘贴的流程”，但暂不作为生产环境

## 正式链路与实验链路

为了避免多人协作把生产链路搞乱，这里明确两条链路：

### 正式链路

- 本地自动化总控
- 正式台账与审计
- 任何会导致真实投注行为的逻辑

这条链路只允许在本地环境跑。

### 实验链路

- 云端电脑开发
- 前端改动
- Colab 训练
- 数据获取层实验

实验链路可以并行推进，但必须通过 PR 合并回仓库。

## 交接流程

任何任务切换执行者前，必须更新：

- `docs/agent_handoff.md`
- 本文件对应任务的状态

交接时必须明确：

1. 当前分支
2. 已完成什么
3. 还差什么
4. 禁止事项

## 风险提示

以下事项发生时，所有智能体应停止继续推进并汇报：

- 需要执行数据库迁移但不确定顺序
- 需要重写自动化总控的关键逻辑
- 需要操作真实台账或真实投注相关文件
- 需要做强推、硬重置、清理工作区等高风险 Git 操作
