# 智能体交接模板

这份文档用于在不同智能体之间做任务交接。它不是“长期项目说明书”，而是每次切换执行者时都可以快速更新的一页记录。

适用场景：

- 你把任务从 Trae Work 转交给 Codex
- 你把任务从本地 Codex 转给 Coze 云端电脑
- 你想让 Claude Code / OpenClaw / Hermes 接手一个局部任务

## 使用原则

1. 只写对下一位执行者真正有用的信息
2. 不重复抄整份 README
3. 明确“当前状态、下一步、禁止事项”
4. 交接时优先贴文件路径、命令和分支，而不是长篇聊天记录

## 模板

复制下面模板使用：

```md
# 当前交接

## 任务名称

<一句话说明当前任务>

## 当前分支

`<branch-name>`

## 当前目标

- <本次要完成什么>
- <成功标准是什么>

## 已完成

- <已经改了哪些文件>
- <已经验证了什么>

## 未完成

- <还差什么>
- <卡在哪里>

## 必看文件

- `<path>`
- `<path>`
- `<path>`

## 推荐命令

```powershell
<command>
<command>
```

## 禁止事项

- <不要改什么>
- <不要推到哪个分支>
- <不要运行什么高风险操作>

## 备注

- <需要注意的环境、凭据、依赖、产物位置>
```

## 简版示例

```md
# 当前交接

## 任务名称

补齐 GitHub 协作与云端开发规范

## 当前分支

`docs/cloud-collaboration`

## 当前目标

- 新增根目录协作文档
- 更新 README 文档入口

## 已完成

- 已确认根目录 README、.gitignore、CI 存在
- 已确认 `football-predictor/` 是唯一正式 Python 工程

## 未完成

- 还没补 Colab 说明
- 还没写 GitHub 工作流文档

## 必看文件

- `README.md`
- `football-predictor/docs/repository_governance.md`
- `docs/collaboration_playbook.md`

## 推荐命令

```powershell
git status --short
.\scripts\project.ps1 test
```

## 禁止事项

- 不要直接 push 到 `main`
- 不要把 `artifacts/` 和 `data/manual/` 提交到 Git

## 备注

- 本地 Codex 正在运行自动化总控，提交前先检查工作区状态
```

## 哪些内容应该写进交接

适合写进来的内容：

- 当前任务到底在做什么
- 当前所在分支
- 已修改的关键文件
- 还缺什么
- 下一位必须先看的路径
- 有风险的操作

## 哪些内容不要写进交接

不建议写：

- 大段重复背景介绍
- 和当前任务无关的长期历史
- 复制整份聊天记录
- 只写“继续开发”这种没有信息量的话

## 推荐做法

每次重要切换前，至少补这 5 项：

1. 当前分支
2. 当前目标
3. 已完成
4. 未完成
5. 禁止事项

如果任务涉及 Git、数据库、自动化调度、Colab 或正式生产链路，交接文档必须更新后再切换执行者。
